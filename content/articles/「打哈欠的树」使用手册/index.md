感谢 AI 义夫，这份手册讲两件事：**怎么管理内容**，**怎么自定义全站**。

## 内容管理：文章

文章放在 `content/articles/` 下，一篇长文对应一个文件夹。

### 新建一篇草稿

```bash
hugo new articles/我的新文章/index.md
```

命令会生成一个文件夹和 `index.md` 草稿。也可以手动创建：新建 `content/articles/我的新文章/` 文件夹，再在里面放一个 `index.md`。图片与正文放同一个文件夹，写起来和管理起来都最方便。

### Front matter 字段

文件最上方的 `---` 之间是文章的元信息（front matter），常用字段如下：

| 字段 | 作用 |
| --- | --- |
| `title` | 标题，显示在文章页顶部和列表页 |
| `date` | 发布时间，决定首页时间线的排序 |
| `tags` | 标签，多个标签用 `["a", "b"]` 格式，会自动聚合到标签页 |
| `summary` | 摘要，列表页上的一句话介绍，建议填写 |
| `draft` | 是否草稿，`true` 时不会发布 |

### 正文写作要点

- **标题层级**：用 `##`（H2）和 `###`（H3）组织小节，文章页会自动生成右侧目录；一级标题 `#` 不进目录，正文里一般不用。
- **代码块**：用三个反引号包裹，可标注语言，例如 ` ```python `。
- **图片**：放在文章同目录下，用相对路径引用：`![](图片名.svg)`。
- **引用**：行首用 `>`。
- **列表**：无序用 `-`，有序用 `1.`。

## 内容管理：随记

随记放在 `content/notes/` 下，适合短文本、日常与灵感。

```bash
hugo new notes/我的新随记/index.md
```

随记**可以没有标题**——把 front matter 里的 `title` 省略即可，页面会用日期作为标题。想发「纯图片随记」，正文里只放一张图片就行：

```md
![傍晚的窗](evening-window.svg)
```

但建议还是多少加几个字，在时间线里排版比较好看。

## 内容管理：关于页

关于页在 `content/about/index.md`，内容包括个人介绍、头像和联系方式：

- **文字**：直接编辑 `index.md` 的正文；
- **头像**：`content/about/avatar.svg`，替换成自己的图片（同名即可，无需改代码）；
- **联系方式**：正文里的 GitHub、邮箱、RSS 链接，按需增删。

## 内容管理：草稿与发布

`draft: true` 的文章**不会发布**。发布一篇内容只需要三步：保存 → 提交推送 → 等待自动上线。

```bash
hugo server -D                     # ① 本地预览（-D 会显示草稿），浏览器打开 http://localhost:1313
git add .                          # ② 把改动加入暂存
git commit -m "anything you want"  # ③ 提交一个版本
git push origin main               # ④ 推送到 GitHub，触发自动发布
```

推送后等一两分钟，GitHub Actions 会自动构建并发布到 GitHub Pages。访问自己的站点（<https://yawningtree.github.io/>）就能看到新内容了。整个过程里**不需要手动构建、不需要碰服务器**。

## 内容管理：修改提交记录

提交时写的「comment」（`git commit -m "..."` 里的那句话）随时可以改。

### 只改最近一次提交

还没推送时最省事，直接改写最近一次提交的说明：

```bash
git commit --amend -m "新的提交说明"
```

### 改更早的提交

用交互式变基（rebase）改任意一条历史提交的说明：

```bash
git rebase -i HEAD~3    # 数字 3 表示回看最近 3 条提交，按需调整
```

会打开编辑器列出这些提交，把想改的那一条前面的 `pick` 改成 `reword`，保存退出；接下来会逐个打开要改的提交，把说明改成新的，保存退出即可。

### 已经推送了怎么办

提交已经推送（线上已发布）时，改完历史后需要强制推送：

```bash
git push --force-with-lease
```

注意：强制推送会重写远端历史。

## 内容管理：整理与删除

- **下架**：把文章的 `draft` 改为 `true`，再提交推送，内容就会从线上消失（草稿仍在本地，随时可以重新发布）。
- **删除**：删掉整个内容文件夹（包括 `index.md` 和图片），提交推送即可。
- **标签习惯**：写文章时给 `tags` 填一致的关键词，站点会自动生成标签聚合页。建议维护一套稳定、少量（比如 5~10 个）的标签，避免越用越乱。

## 全站自定义：站点信息

站名、简介、副标题、作者、起始年份都在站点配置（`hugo.toml`）里：

| 配置项 | 作用 |
| --- | --- |
| `title` | 站名，出现在浏览器标签、页头品牌和页脚 |
| `params.author` | 作者名，出现在页脚 |
| `params.description` | 站点简介，用于页面描述与 SEO |
| `params.tagline` | 副标题，写在首页和页脚附近 |
| `params.since` | 建站年份 |

改完保存，本地预览刷新即可看到效果；提交推送后全站生效。

## 全站自定义：外观

配色、字体、圆角等全部由主题的 CSS 变量控制，位置在 `themes/yawningtree/assets/css/style.css` 顶部的 `:root` 里。改一处，**全站同步生效**：

| 变量 | 含义 |
| --- | --- |
| `--bg` / `--bg-soft` / `--card` | 背景纸色、辅助底色、卡片色 |
| `--ink` / `--ink-soft` / `--ink-faint` | 正文墨色、次级文字、浅淡文字 |
| `--accent` / `--accent-ink` / `--accent-soft` | 强调色（鼠尾草绿）、强调文字色、强调浅底 |
| `--clay` / `--clay-soft` | 陶土色（随记专用）及其浅底 |
| `--serif` / `--sans` / `--mono` | 衬线、无衬线、等宽三种字体栈 |
| `--radius` / `--shadow` | 圆角与阴影 |

例如想换一个更清爽的蓝色系，把 `--accent` 和 `--accent-soft` 改成低饱和的蓝即可；想换字体，改 `--serif` 那几行。改完刷新浏览器（本地预览会自动热更新），确认满意后再提交推送。

## 全站自定义：导航与页脚

- **导航菜单**：在 `themes/yawningtree/layouts/partials/header.html` 里，可以增删「首页 / 文章 / 随记 / 关于」链接，也可以改品牌名「打哈欠的树」。
- **页脚**：在 `themes/yawningtree/layouts/partials/footer.html` 里，改版权行与副文案。
- **站点图标**：浏览器标签页上的小图标在 `static/favicon.svg`，替换成自己的图标即可。
- **关于页头像**：`content/about/avatar.svg`（见上文）。

这些都是日常最常用的自定义入口；更深层的结构调整（比如新增一个内容板块）需要动主题布局，本文不展开。

## 常见问题

- **改了不生效？** 本地预览先按 `Ctrl+C` 重启；如果改的是 CSS，也可以清理缓存目录 `resources/` 后再预览。线上要看 GitHub Actions 跑完（通常一两分钟）。
- **文章为什么没有出现？** 检查 `draft` 是否已经是 `false`；另外 `date` 如果写成了未来日期，Hugo 默认不会发布。
- **图片不显示？** 图片要和 `index.md` 放在**同一个文件夹**，并用相对路径 `![](图片名.svg)` 引用。
- **没有目录？** 用 `##` 和 `###` 组织小节，H2/H3 才会进入自动目录。
- **`public/` 目录要不要管？** 不用。它是构建产物，会被自动重新生成，改它没有意义，也不要提交它。
